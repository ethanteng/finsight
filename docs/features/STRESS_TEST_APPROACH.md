# Stress Test Approach

This document describes the **retirement portfolio stress test** as implemented in the Finsight retirement analytics module. It covers sequence generation, withdrawal simulation, outcome analysis, and how results are interpreted.

---

## Overview

The stress test evaluates whether a user's planned withdrawal amount would have sustained their portfolio across historical market sequences. It answers: *"If retirement had started at various points in history, would the portfolio have survived the withdrawal period without depletion?"*

The approach uses **rolling historical sequences** of real market returns (US equity, international equity, bonds, cash) from a unified CSV dataset and simulates **inflation-adjusted** withdrawals month-by-month with **annual portfolio rebalancing**. Results include survival rate, depletion percentiles, and worst-case sequences by depletion, drawdown, and recovery time.

**Fully deterministic and offline.** No ETF or FRED API calls at runtime.

---

## Pipeline

```
src/datasets/*  →  build-market-dataset.ts  →  data/historical_market_returns.csv  →  historical-data-loader.ts  →  stress test engine
```

The stress test runs as part of the retirement analysis pipeline in `src/retirement-analytics/index.ts`:

```
Phase 1: Portfolio analysis & mapping
Phase 2: Data provider initialization
Phase 3: generateRollingSequences(withdrawalYears, ...)
Phase 3b: computeHistoricalWithdrawalRates(sequences, portfolioMapping, totalValue)
Phase 4: simulateWithdrawals(portfolioMapping, totalValue, sequence, annualWithdrawalAmount) for each sequence
Phase 5: analyzeOutcomes(outcomes, sequences, totalSequences, historicalWithdrawalRates)
Phase 6: Format output for LLM consumption
```

## Phase 3: Sequence Generation

**File:** `src/retirement-analytics/engine/stress-tester.ts`  
**Function:** `generateRollingSequences(withdrawalYears, dataProviderFactory, fredProvider, minHistoryYears)`

### Data Source

The runtime engine reads only **`data/historical_market_returns.csv`**. This file is generated by `scripts/build-market-dataset.ts`, which transforms local datasets in `src/datasets/`:

| Source | File | Columns used |
|--------|------|--------------|
| Shiller | `ie_data.xls` | US equity (P, D), bonds (col 17), inflation (CPI) |
| Kenneth French | `F-F_Research_Data_Factors.csv` | Cash (RF = 1-month T-bill) |

**International equity:** Uses US equity as proxy (`intl_equity = us_equity`). International diversification is not currently modeled. Mkt-RF is US market excess return, not international.

Run `npm run build:market-dataset` to regenerate the CSV. No downloads or API calls.

### Horizon

The user's withdrawal horizon is **exact** (`lifeExpectancy - withdrawalStartAge`). No bucketing to 10/20/30 years.

### No Truncation

Sequences are generated only when **full horizon data exists**. `latestStartDate = today - (withdrawalYears × 12) months`. Sequences starting after this date are excluded. All sequences have complete horizon data.

### Rolling Windows

- **Granularity:** Monthly (every month is a potential start date)
- **Sequence length:** Exactly `withdrawalYears × 12` months
- **Date range:** From the earliest date in `historical_market_returns.csv` to `latestStartDate`

### Sequence Structure

Each `HistoricalSequence` contains:

- `startDate`, `endDate`, `sequenceId` (e.g. `"1973-01_to_1999-12"`)
- `assetBasketReturns`: monthly returns for `usEquity`, `internationalEquity`, `nominalBonds`, `cash`
- `inflationRates`: monthly inflation (MoM) for the sequence's date range

## Phase 4: Withdrawal Simulation

**File:** `src/retirement-analytics/engine/withdrawal-simulator.ts`  
**Function:** `simulateWithdrawals(portfolioMapping, initialPortfolioValue, sequence, annualWithdrawal)`

### Inflation-Adjusted Withdrawals

Withdrawals are defined as "today's dollars" and grow with CPI each month:

```
monthlyWithdrawal = annualWithdrawal / 12
Each month: monthlyWithdrawal *= (1 + inflationRate)
```

This maintains **constant real spending**.

**Withdrawal timing:** Withdrawals are modeled at the **end of each monthly period** after market returns are applied.

### Annual Portfolio Rebalancing

The simulator tracks four asset sleeves (usEquity, internationalEquity, bonds, cash). Each month:

1. Apply asset returns to each sleeve
2. Sum to portfolio value
3. Inflate withdrawal, subtract from total
4. If year-end: rebalance to target weights
5. Else: scale sleeves proportionally to reflect withdrawal

### Simulation Logic

1. **Apply returns** to each sleeve
2. **Inflate withdrawal:** `monthlyWithdrawal *= (1 + inflationRate)`
3. **Subtract withdrawal** from total portfolio value (not from individual sleeves)
4. **Depletion check:** If `portfolioValue <= 0`, return failure
5. **Drawdown/recovery tracking**
6. **Annual rebalance** when `(month + 1) % 12 === 0`; else scale sleeves proportionally to reflect withdrawal

### Drawdown and Recovery

- **Peak:** `peakValue = Math.max(peakValue, portfolioValue)` each month
- **Drawdown:** `(peakValue - portfolioValue) / peakValue`
- **Recovery:** When portfolio exceeds prior peak; `timeToRecovery` = months from drawdown start to recovery (or null if never recovered)

## Phase 5: Outcome Analysis

**File:** `src/retirement-analytics/engine/outcome-analyzer.ts`  
**Function:** `analyzeOutcomes(outcomes, sequences, totalSequences, historicalWithdrawalRates)`

### Survival Rate

```
survivalRate = count(outcomes where withdrawalSustainability === true) / outcomes.length
```

### Depletion Percentiles

Among sequences that **failed**, percentiles of `yearsUntilDepletion`. When all survive, percentiles are null (N/A).

### Worst Sequences

1. **byDepletion:** Failed sequences, soonest depletion first
2. **byDrawdown:** All sequences, largest drawdown first
3. **byRecovery:** Longest recovery first

## Historical Data Sources

| Asset | Source | Notes |
|-------|--------|-------|
| US equity | Shiller P, D | D = trailing 12‑month dividend total; monthly ≈ D/12. Total return = priceReturn + (D/12)/price_prev |
| International equity | US equity proxy | `intl_equity = us_equity`; international diversification not modeled |
| Bonds | Shiller col 17 "Bond Returns" | Value is (1 + monthly_return); return = value − 1. Proper return series. Fallback: GS10 yield → (1+y/100)^(1/12)−1 |
| Cash | Kenneth French RF | 1‑month T‑bill; convert percent to decimal (RF/100) |
| Inflation | Shiller CPI | MoM: CPI_t / CPI_(t-1) − 1 |

## Design Choices

### Determinism

The stress test is fully deterministic. Same inputs produce same outputs. No random sampling. See [Determinism in Analytics and LLM Context](DETERMINISM_IN_ANALYTICS_AND_LLM_CONTEXT.md).

### Offline

No ETF or FRED API calls at runtime. All data comes from the pre-built CSV.

### Historical Withdrawal Solver Consistency

`computeHistoricalWithdrawalRates` uses the **same** `simulateWithdrawals` logic as the main stress test. It does not use a simplified simulation model.
